# 시간표 공유

친구들이 **같은 웹 주소**에서 각자 시간표를 등록하고, 서로의 전체 시간표·특정 요일/교시 수업·공강 시간을 조회할 수 있는 모바일 우선 정적 웹사이트입니다.

프론트엔드는 순수 **HTML/CSS/JavaScript**로 구성되어 GitHub Pages에서 실행되며, 학생 시간표 데이터는 **Supabase 공용 DB**에 저장됩니다. 따라서 서로 다른 휴대폰이나 PC에서 접속해도 같은 데이터를 봅니다.

## 주요 기능

- 학생 이름 + 시간표 이미지 등록
- 이미지 미리보기
- 실제 AI 연결 전 데모 시간표 분석
- 월~금, 1~7교시 과목명 직접 수정
- 같은 이름으로 다시 저장하면 기존 시간표 교체
- 모든 학생이 공유한 이름 검색 및 사람별 전체 시간표 조회
- 특정 요일/교시의 모든 학생 과목 및 공강 조회
- 특정 요일/교시의 공강 학생만 조회하고 인원 수 표시
- 조회/공강 화면 진입 시 공용 DB에서 최신 데이터 다시 동기화
- 저장 성공/오류 토스트 및 버튼 로딩 상태
- iPhone, iPad, PC 대응 반응형 UI

## 파일 구성

- `index.html` — 화면 구조, 접근성 마크업, Supabase 공개 설정값
- `style.css` — 모바일 우선 반응형 디자인
- `app.js` — 데모 분석, Supabase 저장/조회, 사람별 조회 및 공강 찾기 로직
- `README.md` — Supabase 및 GitHub Pages 설정 방법

# 1. Supabase 테이블 설정

현재 배포용 파일은 `timetable-finder` Supabase 프로젝트에 연결되어 있습니다. 새 프로젝트에서 다시 구성할 때는 **SQL Editor**에서 아래 SQL을 한 번 실행합니다.

```sql
create table public.students (
  id bigint generated by default as identity primary key,
  name text not null unique,
  updated_at timestamptz not null default now(),
  schedule jsonb not null,
  constraint name_not_empty check (char_length(trim(name)) > 0),
  constraint name_max_length check (char_length(name) <= 30),
  constraint schedule_is_object check (jsonb_typeof(schedule) = 'object')
);

alter table public.students enable row level security;

create policy "누구나 시간표 조회"
on public.students
for select
to anon, authenticated
using (true);

create policy "누구나 시간표 등록"
on public.students
for insert
to anon, authenticated
with check (
  char_length(trim(name)) > 0
  and char_length(name) <= 30
);

create policy "누구나 시간표 수정"
on public.students
for update
to anon, authenticated
using (true)
with check (
  char_length(trim(name)) > 0
  and char_length(name) <= 30
);

grant select, insert, update
on public.students
to anon, authenticated;

grant usage, select
on sequence public.students_id_seq
to anon, authenticated;
```

현재 서비스는 회원가입 없이 친구들이 바로 등록하는 방식이므로 `anon` 사용자에게 읽기/등록/수정 권한을 허용합니다.

> 같은 이름으로 다시 저장하면 이전 시간표가 교체됩니다. URL을 아는 사람이 다른 사람 이름으로 저장할 수도 있으므로, 실제 운영 규모가 커지면 수정 PIN 또는 로그인을 추가하는 것을 권장합니다.

# 2. Project URL과 Publishable Key 연결

현재 전달하는 파일에는 이 프로젝트의 **Project URL**과 **Publishable Key (`sb_publishable_...`)**가 이미 연결되어 있습니다. 다른 Supabase 프로젝트로 바꿀 때만 `index.html` 맨 아래의 다음 부분을 변경합니다.

```html
<script>
  window.TIMETABLE_SUPABASE_CONFIG = {
    url: 'https://YOUR_PROJECT.supabase.co',
    publishableKey: 'YOUR_SUPABASE_PUBLISHABLE_KEY'
  };
</script>
```

예시:

```html
<script>
  window.TIMETABLE_SUPABASE_CONFIG = {
    url: 'https://abcdefghijk.supabase.co',
    publishableKey: 'sb_publishable_xxxxxxxxxxxxxxxxxxxxx'
  };
</script>
```

Publishable Key는 브라우저에서 사용하는 공개용 키입니다. 실제 데이터 접근 권한은 위에서 설정한 RLS 정책으로 제한합니다.

## 절대 넣으면 안 되는 키

다음 키는 `index.html`, `app.js`, GitHub 저장소에 절대 넣지 않습니다.

- `sb_secret_...`
- `service_role` key
- OpenAI API Key
- 기타 서버 전용 비밀 키

# 3. GitHub Pages 실행 방법

1. `index.html`, `style.css`, `app.js`, `README.md`를 저장소 루트에 올립니다.
2. GitHub 저장소의 **Settings → Pages**를 엽니다.
3. **Build and deployment**에서 Source를 **Deploy from a branch**로 선택합니다.
4. Branch를 `main`, 폴더를 `/(root)`로 선택합니다.
5. 저장 후 생성된 GitHub Pages 주소를 친구들에게 공유합니다.

이후 친구들은 모두 같은 주소에 접속합니다.

- 친구 A가 `김민수` 시간표 저장 → Supabase에 저장
- 친구 B가 자기 휴대폰에서 같은 주소 접속 → `김민수` 시간표 조회 가능
- 친구 C가 자기 시간표 저장 → A와 B도 조회 탭을 다시 열면 최신 데이터 확인 가능

브라우저의 localStorage는 학생 데이터 저장에 사용하지 않습니다.

# 데이터 구조

`students` 테이블에는 학생 한 명당 한 행을 저장합니다.

```json
{
  "name": "이강호",
  "updated_at": "2026-08-07T06:00:00.000Z",
  "schedule": {
    "월": ["스포츠 생활2", "생명과학 실험", "화학 실험", "화학 실험", "한국사2", "한국사2", "공강"],
    "화": ["고급 대수", "고급 대수", "고급 미적분", "고급 미적분", "물리학 실험", "화법과 언어", "화법과 언어"],
    "수": ["음악 감상과 비평", "음악 감상과 비평", "인공지능 일반", "고급 대수", "한국사2", "창체", "창체"],
    "목": ["생명과학 실험", "생명과학 실험", "스포츠 생활2", "스포츠 생활2", "인공지능 일반", "인공지능 일반", "공강"],
    "금": ["화학 실험", "물리학 실험", "물리학 실험", "화법과 언어", "음악 감상과 비평", "고급 미적분", "공강"]
  }
}
```

`name`에는 UNIQUE 제약이 있으므로 같은 이름으로 다시 저장하면 Supabase REST API의 `on_conflict=name` upsert를 통해 해당 학생 데이터가 교체됩니다.

# 현재 시간표 이미지 분석

현재 이미지 분석 버튼은 **데모 분석**입니다. 어떤 학생 이름을 입력해도 테스트할 수 있으며, 기본 데모 결과로 이강호 시간표가 표시됩니다. 사용자는 모든 셀을 수정한 후 실제 공용 DB에 저장할 수 있습니다.

다음 단계에서 실제 이미지 분석을 연결할 때는 다음 구조를 권장합니다.

```text
브라우저
  ↓ 시간표 이미지
Supabase Edge Function 또는 별도 서버 API
  ↓
OpenAI 이미지 분석 API
  ↓ 분석 결과만 반환
브라우저에서 사용자 확인/수정
  ↓
Supabase students 테이블 저장
```

OpenAI API Key는 Edge Function/서버 환경 변수에만 저장하고 브라우저 JavaScript에는 넣지 않습니다.
